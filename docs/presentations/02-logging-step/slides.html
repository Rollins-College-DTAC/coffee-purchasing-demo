Data Analytics with AI · Lecture 2

The Logging Step

How an AI agent keeps a record that anyone can check

Raw Coffee Purchasing · reference project · simulated data only

An agent acts without a person watching each step. This lecture explains how it writes down everything it does, so that a person can check, explain and correct its work afterwards.

Learning objectives

By the end of this lecture you can

1

Define a log and an audit trail.

2

Name the project's six log tables and what each records.

3

Trace one held import from its arrival to its decision.

The rule behind this lecture: every step logs the file name, the SQL it ran, the model it used, and any formula with its values.

The Logging Step · 2 / 9

The rule in bold is one of the project's non-negotiable rules. Everything else in this lecture shows how it is put into practice.

Concept 1 · the log

A log is a time-stamped record of what happened

Each log entry says when something happened, what it was, and what it affected. Entries are added, never edited, so the history cannot quietly change.

Example 1 · everyday

A ship's logbook: every hour the crew writes the time, position, speed and weather. After a storm, the log shows what was done and when.

Example 2 · the project

coffee_20261013-1511.csv

The Logging Step · 3 / 9

Stress the append-only property: a log you can edit afterwards proves nothing. In the project, each step writes a row when it starts and fills in its finish time and status when it ends.

Concept 2 · the audit trail

An audit trail lets someone else check every decision

An audit trail is a set of logs complete enough that a person who was not there can rebuild each decision and judge whether it was right. It is the basis of governance: accountability for automated work.

Example 1 · everyday

A bank statement lists every payment with date, amount and payee. You can spot a charge you never made and dispute it.

Example 2 · the project

A buyer asks why an import was held. The logs show the query that fetched past prices, the formula, its values, and the threshold it crossed.

The Logging Step · 4 / 9

The Logging Step · 5 / 9

Each table answers a different question. run_log: what ran, and did it succeed? sql_log: what data did it read or change? model_usage_log: which AI did it ask, why, and at what cost? stats_log: what was calculated, with which inputs? decision_log: what did it decide? incident_log: what needs a person? The run ID ties all six together.

Concept 3 · a single entry point

Every query goes through one door, which writes the log

If logging is optional, someone eventually forgets it. So the project allows one function, run_sql, to touch the database, and that function always records the query.

Example 1 · everyday

A laboratory with one entrance and a sign-in sheet at the door. Nobody can enter without leaving a name and a time.

Example 2 · the project

db.run_sql("decide",
"SELECT ... LIMIT ?",
(run_id, 60))

The ? marks are filled in safely by the database, and both the query and the values land in sql_log.

The Logging Step · 6 / 9

Placeholders, the question marks, keep data separate from commands. If a supplier's note contained SQL text, it would be stored as text, never run as a command. This is SQL injection prevention, a close cousin of the prompt-injection defense taught in the Jev lecture.

Concept 4 · a good entry

A good entry answers what, when, which, why, and never holds a secret

Example 1 · everyday

Weak: "gave meds"

Strong: "Ibuprofen 400 mg, by mouth, 14:05, Nurse K., for fever of 38.6 °C"

Example 2 · the project

Weak: "called the AI"

Strong: "jev · classify · reason: classify questions go to Jev · 63 ms · confidence 1.00 · $0.00004"

Never log a key or password. When the project checks an API key, it logs only "set, 108 characters", never the key itself.

The Logging Step · 8 / 9

Logs are often read by more people than the code, and are stored for a long time. Anything secret written into a log should be treated as leaked. Personal data deserves the same care, which is why the project masks emails and phone numbers before notes reach any model.

The Logging Step · 9 / 9

Answers. 1: model_usage_log, which stores the expert and the route reason for every call. 2: so that logging cannot be forgotten or skipped; the only way to reach the database writes the log. 3: for example, "coffee_20261013-1511.csv held at 15:11: mean $4.46/lb, z = −3.13 against the last 10 imports (threshold 3); incident opened".
