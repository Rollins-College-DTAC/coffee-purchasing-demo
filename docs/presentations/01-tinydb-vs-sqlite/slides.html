Read the definition of a database aloud. Ask: where have you used one today? Answers might include a phone's contact list or a library catalogue; both are databases.

The problem

The same facts arrive in different shapes

A CSV file (a table as text)

lot_id,origin,price,price_unit
LOT-0000-00,ETH,5.80,$/lb
LOT-0000-01,Columbia,10.14,USD/kg

A JSON file (labeled fields)

{"lotId": "LOT-0001-00",
"Origin": "Kenya Nyeri",
"price": "6.87 USD/lb"}

Field names differ (lot_id vs lotId), units differ ($/lb vs USD/kg), and names are misspelled (Columbia). We must keep this exactly as received, and also turn it into one clean shape.

TinyDB vs SQLite · 3 / 9

These records come from the project's generator, which makes the data messy on purpose. CSV is comma-separated values: a table written as plain text. JSON is JavaScript Object Notation: each value has a label. Ask students to find three differences between the two records before revealing the caption.

Concept 1 · TinyDB

A document database stores each record as it is

Each record is a self-contained document. Two records need not have the same fields. TinyDB keeps all documents in one JSON file.

Example 1 · everyday

A box of index cards. One card holds a recipe, the next a phone number; each card can say anything.

Example 2 · the project

data/raw.json keeps both records from the previous slide unchanged, each tagged with its file name, hash and arrival time.

TinyDB vs SQLite · 4 / 9

Key point: a document database does not force a structure, so nothing is lost on arrival. That flexibility is also its weakness: averaging prices is hard when some records say lot_id and others lotId, and prices carry units inside the text.

Concept 2 · SQLite

A relational database stores rows in fixed tables

Every row in a table has the same columns, and every column has one type, such as text or number. We ask questions in SQL, Structured Query Language.

Example 1 · everyday

A teacher's gradebook: one row per student, one column per test, a number in every cell. Averaging a column is easy.

Large organizations use the same two ideas at scale: document stores such as MongoDB, and relational databases such as PostgreSQL or cloud warehouses such as Snowflake, which this project can also load into. The concepts transfer; only the size changes.

TinyDB vs SQLite · 7 / 9

This is the raw-versus-clean layer pattern used across the data industry, sometimes called bronze, silver and gold. Raw data is evidence; the clean layer is our interpretation of it. If a cleaning rule is wrong, we fix the rule and clean again from raw, without asking the supplier to resend anything.

Asking questions

A query is a question the database answers

TinyDB, in Python

1. Every record from one file

raw.search(Query()._file_name
== "coffee_20261013-1511.csv")

2. One lot by its ID

raw.search(Query().lot_id
== "LOT-0072-08")

SQLite, in SQL

1. Average price of Kenyan lots

SELECT AVG(price_per_lb)
FROM purchases WHERE origin = 'Kenya';

2. How many lots per origin

SELECT origin, COUNT(*)
FROM purchases GROUP BY origin;

TinyDB vs SQLite · 8 / 9

TinyDB queries find records; SQL queries can also calculate across them. Read the SQL aloud as English: select the average price per pound from purchases where the origin is Kenya. In the project every SQL query passes through one function, run_sql, which records it in the sql_log table; that is the subject of the logging lecture.

Check your understanding

Three questions

  1. A new supplier sends a file with a field called vendor_name. Which database accepts it unchanged, and why?
  2. You need the average $/lb of Brazilian coffee this week. Which database do you ask, and in which language?
  3. A cleaning rule turned "Columbia" into "Bolivia" by mistake. What lets you repair the data without asking the supplier?

TinyDB vs SQLite · 9 / 9

Answers. 1: TinyDB, because documents need not share fields. 2: SQLite, with an SQL query such as SELECT AVG(price_per_lb) FROM purchases WHERE origin = 'Brazil'. 3: the raw layer in TinyDB still holds the original record, so you fix the rule and clean again.
